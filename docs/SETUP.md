# Setup — from zero to a live, verified deployment

In order, assuming nothing already exists.

## 1. Neon (Postgres)

Project `lively-cell-80315368` already exists with a `production` branch.
If you're starting completely fresh instead:

1. Sign in at [neon.tech](https://neon.tech) (free tier, no credit card).
2. New Project → name it `ascend` → default Postgres version is fine.
3. **Connection Details** panel → toggle **off** "Pooled connection" — you
   need the **direct** connection string. Copy it; it looks like:
   ```
   postgresql://<user>:<password>@ep-xxxx.<region>.aws.neon.tech/<dbname>?sslmode=require
   ```
   This exact string becomes `DATABASE_URL`. Do not use the pooled
   (PgBouncer) string — psycopg3's server-side prepared statements aren't
   compatible with transaction-mode pooling, and `ascend/settings.py`
   assumes the direct connection (`prepare_threshold=None`, `CONN_MAX_AGE=0`
   compensate for not pooling ourselves, which is fine at this traffic
   volume).

## 2. GitHub

1. Create an empty repository (no README/gitignore template — this repo
   brings its own).
2. From `ASCEND-backend/`:
   ```bash
   git init
   git add -A
   git commit -m "Initial ASCEND backend"
   git remote add origin <your-repo-url>
   git push -u origin main
   ```

## 3. Render (web service)

1. Sign in at [render.com](https://render.com) (free tier, no credit card).
2. New → Web Service → connect the GitHub repo you just pushed.
3. Render reads `render.yaml` from the repo root automatically (Blueprint
   deploy) — plan `free`, Python runtime, build command installs deps,
   collects static files, and runs migrations; start command runs gunicorn.
4. Fill in the env vars `render.yaml` marks `sync: false` (Render prompts
   for these during setup, or add them after under **Environment**):
   - `DATABASE_URL` — the Neon direct connection string from step 1.
   - `INGEST_TOKEN` — generate one: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.
     Keep this secret — it's the bearer credential for every scheduled
     Claude task and both iPhone Shortcuts.
   - `CORS_ALLOWED_ORIGINS` — your frontend's origin once it exists (e.g.
     `https://ascend-frontend.vercel.app`); leave blank until then.
   - `INGEST_OWNER_USERNAME` — leave blank until you've created your
     superuser in step 4; it defaults to "the first superuser found," which
     is exactly right for a single-user deployment.
   - `SECRET_KEY` is auto-generated by Render (`generateValue: true`) — you
     don't need to set this.
5. Deploy. Watch the build logs; migrations (including the seed data
   migration) run automatically. First deploy takes a few minutes.

## 4. Create your superuser

Render dashboard → your service → **Shell** tab:

```bash
python manage.py createsuperuser
```

Pick any username/email/password — this is the one human account. Then,
in the same shell, mint your API token for the frontend and for curl
testing:

```bash
python manage.py shell -c "
from django.contrib.auth import get_user_model
from rest_framework.authtoken.models import Token
user = get_user_model().objects.get(is_superuser=True)
token, _ = Token.objects.get_or_create(user=user)
print(token.key)
"
```

Save that token somewhere — it's your `Authorization: Token <key>` header
for `/api/analytics/*` and the block-tap endpoints. It is a **different**
credential from `INGEST_TOKEN`.

## 5. Verify it's actually live

```bash
curl https://<your-service>.onrender.com/api/health/
```

Should return `{"status": "ok", "db": "ok", ...}`. If it doesn't, check the
Render logs before going further — everything past this point assumes a
working deployment.

Run the fuller check (see [the verify script](../scripts)):

```bash
./scripts/verify.sh https://<your-service>.onrender.com <your-user-token> <your-ingest-token>
# or on Windows:
./scripts/verify.ps1 -BaseUrl https://<your-service>.onrender.com -UserToken <token> -IngestToken <token>
```

## 6. Keep it warm (cron-job.org)

Render free services sleep after 15 minutes idle, and the first request
after sleeping eats a ~30-60s cold start.

1. Sign up at [cron-job.org](https://cron-job.org) (free).
2. Create a new cron job:
   - URL: `https://<your-service>.onrender.com/api/health/`
   - Schedule: every 10 minutes
   - Method: GET, no auth needed (health is `AllowAny`)
3. Save. That's it — as long as this job runs, your service never fully
   sleeps, and both scheduled Claude tasks (10:00 and 22:00) hit a warm
   instance instead of eating the cold-start penalty.

## 7. Wire up the two Shortcuts and the two Claude tasks

- [SHORTCUTS.md](SHORTCUTS.md) — sleep tracking automations.
- [CLAUDE_TASK_PAYLOADS.md](CLAUDE_TASK_PAYLOADS.md) — paste-ready prompts
